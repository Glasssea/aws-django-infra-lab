AWS Django Infrastructure Deployment

Overview

기존 Django 프로젝트를 실제 AWS 환경에서 직접 운영해보며 서버와 네트워크 인프라를 이해하고 싶었습니다. 이 포트폴리오 사이트 자체가 아래 인프라 위에서 직접 구성한 서버로 서비스되고 있습니다.

Deployment Flow

EC2 → Ubuntu → Swap → MySQL → Gunicorn + systemd → Nginx → Elastic IP / Security Group → LIVE

Architecture

Client → Nginx → Gunicorn (Unix Socket) → Django → MySQL 8.0

EC2 t3.micro · Ubuntu 24.04 · 1GiB RAM · 2GB Swap

AWS Nginx Gunicorn Django MySQL systemd Unix Socket Elastic IP Security Group

Configuration

  • AWS EC2 Ubuntu 인스턴스 구성
  • Security Group으로 SSH(22) / HTTP(80) 접근 제어
  • EBS 저장공간을 활용해 2GB Swap File 구성 (t3.micro 1GiB RAM 보완)
  • Nginx를 Reverse Proxy로 구성
  • Gunicorn을 systemd 서비스로 등록하여 Django 애플리케이션 실행
  • Unix Socket을 통해 Nginx와 Gunicorn 연동
  • MySQL 8.0 데이터베이스 구성 및 Django 연결
  • Elastic IP를 사용하여 고정 Public IP 구성

Troubleshooting

  • Nginx static 403 → 실행 사용자(www-data)의 디렉토리 권한 확인 후 조정
  • t3.micro(1GiB RAM) 메모리 제약 → EBS 저장공간을 활용한 2GB Swap File 구성
  • Gunicorn 실행 문제 → systemd 상태 및 로그 확인으로 원인 추적

Riot ID와 태그를 입력하면 최근 게임 전적과 챔피언, KDA, 아이템 등의 정보를 확인할 수 있습니다.

SVD Recommendation System

TrollBatta의 소환사 검색 결과 화면에 연결되어 있는 추천 시스템입니다.

How It Works

  • Riot API로 소환사의 챔피언 숙련도(Champion Mastery) 데이터를 수집합니다.
  • Pandas로 데이터를 사용자 × 챔피언 pivot 테이블 형태로 가공합니다.
  • scikit-learn의 TruncatedSVD로 차원을 축소한 뒤 복원(inverse_transform)하여, 적게 플레이했지만 예측 선호도가 높은 챔피언을 찾습니다.
